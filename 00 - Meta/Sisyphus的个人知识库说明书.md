# 🧠 个人知识管理系统

# 黄金法则
- 以始为终————以“我要解决什么问题”倒推“我要收集什么知识”
- 输出倒逼输入———用自己的话复述转化每个知识
- 层级划分依据
	- 无从下手 ：【Inbox】
	- 搬运汇总 ：【Resources】
	- 自己的思考 ：【Areas】
	- 复盘+待办 ：【Review】
	- 中短期目标 ：【Projects】
	- 消化完成 ：【Archives】

## 1\. 系统架构：PARA 变体层级

*本架构核心：不按学科分类，按“行动状态”分类，解决知识淤积。*

• **01 Projects（项目）**：正在进行、有明确交付日期的任务（如：某AI工具开发）。

• **02 Areas（领域）**：长期关注且需维持高水平的范畴（如：技术栈、思维方法、感悟）。

• **03 Resources（资源）**：存放原料的一手知识区，知识加工采集的矿山（如：摘录、大纲结构、原版文章等）

• **04 Archives（归档）**：已结束的项目、不再活跃的兴趣、过期的日记（冷备份数据库）。

• **05 Inbox（收件箱）**：“分流”信息/知识的缓冲区，短时间内处理以防囤积。

• **06 Review（复盘）**：复盘笔记。

## 2\. 核心元数据（Metadata）标准

*每篇笔记的“身份证”，强制实现从“囤积”到“应用”的转化。*

• \`category\`: 笔记类型（技术/复盘/思维/感悟等）。 **【用标签“细分”领域】**

• \`status\`: 加工进度（📥收集 / 🌱加工 / ✅沉淀）。 **【用描述“加工进度”的方式防止知识库为半成品】**
	- 📥收集: 原始内容含量极高、未被消化的原材料。
	- 🌱加工：思考的活跃区、内容未完全闭环的部分。
	- ✅沉淀：完成“自己话复述”和设置“应用场景”阶段后形成的“积木”——原子化知识。

• \`project\`: 关联的项目（使用 \`\[\[项目名称\]\]\` 强关联）。**【将碎片化的知识“打包”到具体实践】**

• \`source\`: 加工知识的溯源通道，。**【为二手知识提供一手知识背书，返回“案发现场”】**

• \`application\`: **核心字段**。写明此知识在什么具体场景下能解决什么问题。**【知识要服务场景】**

## 3\. 笔记记录金律（模板逻辑）

*拒绝全文剪藏，强制原子化思考。*

• **技术/思维类**：必须包含“核心结论”、“我的见解”、“场景设想”。**无场景，不记录。** 

• **复盘类**：遵循“事件回顾”、“5-Whys 根因分析”、“未来规则 (SOP)”。

• **感悟/名言类**：必须经过“重述”和“联想”，标记为“触发心境”使用。

## 4\. 自动化与抗膨胀原则

*保持系统轻量化，防止沦为垃圾场。*

• **日记双区治理**：上方为“行政区”（待办事项 \`\#task\`），下方为“闪念区”（知识提炼）。

• **定期分流**：每周复盘日记，有价值的升级为原子笔记，无价值的留在日记中归档。

• **三不记原则**：不记已知事实、不记无感知摘录、不记模糊情绪。

• **搜索优化**：将 \`04 Archives\` 设为搜索排除目录，保持工作区纯净。

## 5\. 核心工具链

*严禁过度工具化，只保留核心动力。*

1\. **Dataview**: 自动化索引引擎。
- 做「汇总」：比如周复盘，你想看这周写了多少篇技术笔记。
- 做「关联」：比如在项目 A 的页面，自动显示所有被打上项目 A 标签的原子笔记。
- 做「提醒」：比如在 Dashboard 过滤出所有 `status` 停留在 `🌱 加工` 超过一周的笔记（防遗忘）。

2\. **Templater**: 一键调用标准模板。

3\. **Recent Files**: 快速切换上下文。

4\. **Tasks**: 聚合管理日记中的待办事项。

## 6\. 标签规范（Tag 标准）

*标签只表达「这篇笔记讲什么主题」，不表达「笔记放在哪个文件夹」（文件夹按 PARA 行动状态分，两者解耦）。*

**格式**：一律写在 YAML frontmatter 的 `tags:` 字段，禁止在正文第一行写 `#xxx` 内联标签。

**命名**：纯中文 + `AI` 专名，层级用 `/` 分隔，不混用大小写（避免 Dataview 按大小写拆出重复标签）。

**顶层主题域（7 个）**：

| 顶层 | 二级 | 说明 |
|---|---|---|
| `AI` | `/基础` `/提示词` `/工具` `/应用` | LLM、Agent、提示词、AI 工具与 AI 应用 |
| `编程` | `/基础` `/框架` `/数据库` `/中间件` `/源码` `/运维` `/工程化` | 技术知识按主题细分 |
| `思维` | `/框架` `/模式` `/感悟` | 思维框架、模式库、感悟 |
| `人生` | `/规划` `/家庭` `/求职` | 人生目标、家庭事务、求职 |
| `小说` | | 小说创作 |
| `复盘` | | 复盘笔记 |
| `项目` | | 项目笔记 |

**规则**：
- 一篇笔记优先用 1~2 个主题标签，跨主题可多打，但不要堆叠无意义的标签。
- 删除旧体系标签：`Areas/...`、`Resources/...`、`Coder`、`coder`、`master-notebook` 等一律不用。
- 新笔记由模板创建时自动带默认标签，按需微调即可。
