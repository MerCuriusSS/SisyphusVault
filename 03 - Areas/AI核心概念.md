### LLM(Large Language Model)
- 定义：大语言模型，基于「Transformer」，决策大脑，本质上就是一个概率模型，根据已有的文本预测下一个 token 出现的概率，一个字一个字地往外蹦，靠规模效应做到惊人地准确

### Prompt：
- 定义：输入到LLM的指令
	- #### System Prompt：对话开始前由开发者/系统设置的**指令**，用于设定 LLM 的行为、风格、角色、规则等。【具有强制性约束】
	- #### User Prompt：用户输入的内容。【具备软性约束，容易被淹没】

### 思维链（chain-to-thought CoT）：
- 定义：让模型把推理过程写出来再给答案，等价于给自己打草稿，每一步的中间结果都成了后续推理的输入，准确率自然更高

### Context
- 定义：与大模型的对话历史（大模型记忆本质就是每次对话都读取整个对话历史）

### 自动记忆
- 定义：Agent 自动识别对话中跨会话有价值的信息（用户偏好、项目规范等），沉淀到记忆文件里，新会话启动时自动加载到上下文。

###  RAG（检索增强生成）
- 定义：对原始资料进行分片存储，用户提问时从中检索语义最相关的片段作为参考生成答案。
- 组成部分:
	- 原始资料
	- 向量模型（`EmbeddingModel`）
	- 向量数据库
- 执行流程：
	- 提问前
	- 提问后

```
提问前：
1.原始资料进行「分片」
2.向量模型将「分片」转化为向量（余弦相似度、欧氏距离等算法）
3.以{向量}-{数据分片}的映射关系保存到向量数据库中
```

```
提问后：
1.向量模型将用户提问转化为向量
2.从向量数据库中查询得出N个最相近的片段（召回/粗筛）
3.从N个片段中再筛查出M个相关度最高的片段（重排/精筛）
4.将原用户提问+M个片段信息一起发送给LLM处理。
```
### Function Calling
- 定义：LLM 对于「工具调用」的格式化描述。强调**调用**
- 目的：表达 LLM “调用哪个函数，传入什么参数”的意图，让外围程序实际调用后把结果塞回给上下文。

### MCP（Model Context Protocol）
- 定义：提供给 LLM 进行工具接入的同一规范，也即大模型工具领域中「USB-C」标准。强调**接入**

### Skill
- 定义：记录执行流程的操作文档。强调**流程**

### LangChain
- 定义：将多个相互独立的操作步骤串联并抽象出任务链，以「编程方式」实现可复用、输出可控的工作流。

### **Prompt Engineering**
- 定义：提示词工程，负责告诉模型「做什么，怎么做」，约束大模型的**行为**。
- 意义：让大模型更好地**理解用户意图**。


### **Context Engineering**
- 定义：上下文工程，负责告诉模型「能看到什么」，约束大模型的**参考资料**（样例、参考文献、背景资料等）
- 意义：让大模型更**优质地输出内容**

### **Harness Engineering**
- 定义：主要管搭建包裹模型的整套执行流程，约束**模型外部软件系统**的行为
- 意义：保证包裹模型的软件系统运行稳定、不出安全问题。


**区分是否为 Harness 判定法则：约束是否需要把文字塞进大模型嘴里，靠模型自己阅读理解并自觉遵守的**
