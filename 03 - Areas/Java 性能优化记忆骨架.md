[「记忆规律」与「知识体系建设」](「记忆规律」与「知识体系建设」.md)

```
L1:
如何系统性地定位、解决、验证java后端性能问题？

L2：
定义现象：明确具体问题在哪里——属于哪一类？哪些指标？
基线采集：记录优化前的指标数据
工具定位：日志、监控、链路追踪、压测、profiling
分层优化：根据瓶颈所在层采取相应优化手段
效果验证：同样流量模型比对基线数据
风险复盘：无错误率、无新问题、无瓶颈转移等

L3：
├─ 定义现象 -> 现象类型（响应时间、CPU飙升、内存高）；RT、P95/P99、QPS、CPU、GC、慢SQL等
├─ 基线采集 
├─ 工具定位 -> 监控看资源、链路追踪看耗时分布、日志看业务细节、profiling看热点、压测复现问题
├─ 分层优化 -> 代码、并发线程池、远程调用、数据库、缓存、MQ、JVM、架构
├─ 效果验证 
├─ 风险复盘

L4：
├─ 现象与指标 -> 响应时间（RT、P95/P99）；吞吐量（QPS、池资源）、CPU飙升（TOP、线程栈、火焰图）、内存高（GC日志、heap dump、对象分配）、慢SQL（慢SQL日志、explain、扫描行数）等
├─ 工具定位 -> Prometheus/Grafana 看资源；skywalking看链路耗时；慢SQL日志和explain看数据库；GC 日志、jstat、jmap、jstack、Arthas、MAT 看 JVM；JMeter做压测
├─ 分层归因：
	├─ 代码层：重复调用、无效计算、复杂度、大对象、序列化、日志
	├─ 并发层：线程池、锁、异步化、资源隔离
	├─ 远程调用层：链路长度、超时、重试、熔断
	├─ 数据库层：慢 SQL、索引、深分页、事务、连接池
	├─ 缓存层关注读多写少、穿透、击穿、雪崩、热点 Key、一致性
	├─ MQ 层关注削峰、解耦、主链路缩短、可靠性
	├─ JVM 层关注 GC、内存泄漏、CPU 飙高、线程阻塞
	├─ 架构层关注扩容、分库分表、冷热分离、限流降级、服务拆分

L5：
接口整体慢
数据库扫描行数大
读请求压垮数据库
请求排队严重
CPU 飙高
下游偶发变慢拖垮主流程
高峰流量瞬间打满系统
单点优化后仍不够
```
